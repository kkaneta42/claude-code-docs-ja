# CLI リファレンス

> Claude Code コマンドラインインターフェースの完全なリファレンス。コマンドとフラグを含みます。

## CLI コマンド

これらのコマンドを使用して、セッションを開始し、コンテンツをパイプし、会話を再開し、更新を管理できます。

| コマンド | 説明 | 例 |
| :- | :- | :- |
| `claude` | インタラクティブセッションを開始 | `claude` |
| `claude "query"` | 初期プロンプト付きでインタラクティブセッションを開始 | `claude "explain this project"` |
| `claude -p "query"` | SDK 経由でクエリを実行してから終了 | `claude -p "explain this function"` |
| `cat file \| claude -p "query"` | パイプされたコンテンツを処理 | `cat logs.txt \| claude -p "explain"` |
| `claude -c` | 現在のディレクトリで最新の会話を続行 | `claude -c` |
| `claude -c -p "query"` | SDK 経由で続行 | `claude -c -p "Check for type errors"` |
| `claude -r "<session>" "query"` | セッション ID または名前でセッションを再開 | `claude -r "auth-refactor" "Finish this PR"` |
| `claude update` | 最新バージョンに更新 | `claude update` |
| `claude gateway` | 自己ホスト型 [Claude apps gateway](https://code.claude.com/docs/ja/claude-apps-gateway) サーバーを開始します。Amazon Bedrock、Google Cloud の Agent Platform、または Microsoft Foundry 上の Claude Code の前に SSO とポリシーをデプロイする管理者向けです。`--config` で [`gateway.yaml`](https://code.claude.com/docs/ja/claude-apps-gateway-config) を指す必要があります。 | `claude gateway --config gateway.yaml` |
| `claude install [version]` | ネイティブバイナリをインストールまたは再インストールします。`2.1.118` のようなバージョン、または `stable` または `latest` を受け入れます。[特定のバージョンをインストール](https://code.claude.com/docs/ja/setup.md#install-a-specific-version) を参照してください | `claude install stable` |
| `claude auth login` | Anthropic アカウントにサインインします。`--email` を使用してメールアドレスを事前入力し、`--sso` を使用して SSO 認証を強制し、`--console` を使用して Claude サブスクリプションの代わりに Anthropic Console で API 使用料金をサインインできます | `claude auth login --console` |
| `claude auth logout` | Anthropic アカウントからログアウト | `claude auth logout` |
| `claude auth status` | 認証ステータスを JSON として表示します。`--text` を使用して人間が読める形式で表示できます。ログイン済みの場合はコード 0 で終了し、ログインしていない場合は 1 で終了します。JSON には、CLI が使用する [設定ディレクトリ](https://code.claude.com/docs/ja/claude-directory.md) の名前を付ける `configDirectory` フィールドが含まれます。このフィールドには Claude Code v2.1.268 以降が必要です。JSON の `authMethod` フィールドは、`none`、`claude.ai`、`oauth_token`、`api_key`、`api_key_helper`、または `third_party` のいずれかです | `claude auth status` |
| `claude agents` | [エージェントビュー](https://code.claude.com/docs/ja/agent-view.md) を開いて、並列バックグラウンドセッションを監視およびディスパッチします。`--cwd <path>` を使用して、そのディレクトリの下で開始されたセッションのみを表示するか、`--json` を使用してアクティブなセッションを JSON 配列として出力してスクリプト作成用にします（`--json --all` は完了したバックグラウンドセッションも含みます）。`--permission-mode`、`--model`、`--effort`、または `--agent` を渡して、[ディスパッチされたセッションのデフォルト](https://code.claude.com/docs/ja/agent-view.md#permission-mode-model-and-effort) を設定します。トップレベルの `claude` コマンドと同様に `--settings`、`--add-dir`、`--plugin-dir`、および `--mcp-config` を受け入れます。エージェントビューを開くにはインタラクティブターミナルが必要です | `claude agents --json` |
| `claude attach <id\|name>` | このターミナルで [バックグラウンドセッション](https://code.claude.com/docs/ja/agent-view.md#manage-sessions-from-the-shell) に接続します。ID の代わりに実行中のセッション名の一部を渡すには、Claude Code v2.1.290 以降が必要です | `claude attach 7c5dcf5d` |
| `claude auto-mode defaults` | 組み込み [auto モード](https://code.claude.com/docs/ja/permission-modes.md#eliminate-prompts-with-auto-mode) 分類器ルールを JSON として出力します。`claude auto-mode config` を使用して、設定が適用された有効な設定を確認してください。`--label <prefix>` は、ラベルがそのプレフィックスで始まるルールのみを出力します。大文字と小文字を区別しません。Claude Code v2.1.208 以降が必要です | `claude auto-mode defaults --label 'Git Destructive'` |
| `claude auto-mode reset` | ユーザー設定ファイルから `autoMode` セクションを削除して、デフォルト [auto モード](https://code.claude.com/docs/ja/permission-modes.md#eliminate-prompts-with-auto-mode) 設定を復元します。書き込み前に確認を求めます。`-y`/`--yes` を渡してプロンプトをスキップします。[管理設定](https://code.claude.com/docs/ja/server-managed-settings.md) または `--settings` フラグからのルールは引き続き適用されます。Claude Code v2.1.212 以降が必要です。[デフォルトと有効な設定を検査](https://code.claude.com/docs/ja/auto-mode-config.md#inspect-the-defaults-and-your-effective-config) を参照してください | `claude auto-mode reset --yes` |
| `claude daemon logs` | バックグラウンドセッション [スーパーバイザー](https://code.claude.com/docs/ja/agent-view.md#the-supervisor-process) のログファイル `~/.claude/daemon.log` を追跡し、`Ctrl+C` を押すまで新しい行が届くたびに出力します | `claude daemon logs` |
| `claude daemon run` | バックグラウンドセッション [スーパーバイザー](https://code.claude.com/docs/ja/agent-view.md#the-supervisor-process) をこのターミナルのフォアグラウンドで実行し、そのログを出力します | `claude daemon run` |
| `claude daemon status` | バックグラウンドセッション [スーパーバイザー](https://code.claude.com/docs/ja/agent-view.md#the-supervisor-process) の状態、バージョン、ソケットディレクトリ、および診断用のワーカー数を出力します。スーパーバイザーが実行されていない場合は 1 で終了します | `claude daemon status` |
| `claude daemon stop --any` | バックグラウンドセッション [スーパーバイザー](https://code.claude.com/docs/ja/agent-view.md#the-supervisor-process) とそれがホストするセッションを停止します。`--keep-workers` を渡して、バックグラウンドセッションを実行したままにして、次のスーパーバイザーが再接続できるようにします。`--any` はオンデマンドスーパーバイザーの停止を確認します。これはデフォルトです。これを使用して、[応答しないスーパーバイザー](https://code.claude.com/docs/ja/agent-view.md#agent-view-says-the-background-service-did-not-respond) から回復します | `claude daemon stop --any --keep-workers` |
| `claude doctor` | セッションを開始せずにターミナルから読み取り専用のインストールおよび設定診断を出力します。インストール正常性、設定ファイル検証エラー、および Remote Control 適格性を含みます。セッション内のセットアップチェックアップで修正を適用することもできます。[`/doctor`](https://code.claude.com/docs/ja/commands#all-commands) を実行してください | `claude doctor` |
| `claude import [source]` | 他のコーディングエージェントからの設定を Claude Code に取り込むために [`/import`](https://code.claude.com/docs/ja/commands#all-commands) を実行するインタラクティブセッションを開始します。コマンドと同じ `--dry-run` および `--yes` オプションを受け入れます。Amazon Bedrock、Google Cloud の Agent Platform、Microsoft Foundry、または AWS 上の Claude Platform では利用できません。[機能フラグ取得](https://code.claude.com/docs/ja/env-vars.md#features-that-need-feature-flag-fetching) をオフにした場合も利用できません。Claude Code v2.1.213 以降が必要です | `claude import codex --dry-run` |
| `claude logs <id\|name>` | [バックグラウンドセッション](https://code.claude.com/docs/ja/agent-view.md#manage-sessions-from-the-shell) からの最近の出力を出力します。ID の代わりにセッション名の一部を渡すには、Claude Code v2.1.290 以降が必要です | `claude logs 7c5dcf5d` |
| `claude mcp` | Model Context Protocol（MCP）サーバーを設定 | [Claude Code MCP ドキュメント](https://code.claude.com/docs/ja/mcp.md) を参照してください。 |
| `claude mcp login <name>` | 設定済み MCP サーバーの OAuth フローを実行します。インタラクティブな `/mcp` パネルを開きません。HTTP、SSE、および claude.ai コネクタサーバーで機能します。SSH 経由では `--no-browser` を追加すると、ブラウザを開く代わりに認可 URL を出力します。HTTP または SSE サーバーの場合は、リダイレクト URL をプロンプトに貼り付けます。claude.ai コネクタの場合は、[シェルからコネクタを再度認可する](https://code.claude.com/docs/ja/remote-control.md#authorize-a-connector-again-from-your-shell) を参照してください。[コマンドラインから認証](https://code.claude.com/docs/ja/mcp.md#authenticate-from-the-command-line) を参照してください | `claude mcp login sentry` |
| `claude mcp logout <name>` | MCP サーバーの保存された OAuth 認証情報をクリアします | `claude mcp logout sentry` |
| `claude plugin` | Claude Code [plugins](https://code.claude.com/docs/ja/plugins/overview.md) を管理します。エイリアス：`claude plugins`。サブコマンドについては [plugin reference](https://code.claude.com/docs/ja/plugins/cli-reference.md#claude-plugin-commands) を参照してください | `claude plugin install code-review@claude-plugins-official` |
| `claude purge [path]` | プロジェクトのすべてのローカル Claude Code 状態を削除します：トランスクリプト、タスクリスト、デバッグログ、ファイル編集履歴、プロンプト履歴行、および `~/.claude.json` 内のプロジェクトエントリ。`[path]` を省略して、インタラクティブリストから選択します。フラグ：`--dry-run` でプレビュー、`-y`/`--yes` で確認をスキップ、`-i`/`--interactive` で各項目を確認、`--all` ですべてのプロジェクト。[ローカルデータをクリア](https://code.claude.com/docs/ja/claude-directory.md#clear-local-data) を参照してください | `claude purge ~/work/repo --dry-run` |
| `claude remote-control` | [Remote Control](https://code.claude.com/docs/ja/remote-control.md) サーバーを開始して、claude.ai または Claude アプリから Claude Code を制御します。エイリアス：`claude rc`。サーバーモード（ローカルインタラクティブセッションなし）で実行されます。[サーバーモードフラグ](https://code.claude.com/docs/ja/remote-control.md#start-a-remote-control-session) を参照してください。サーバーを停止した後、サーバーが提供していたセッションを復元できます。[サーバー停止後のセッション再開](https://code.claude.com/docs/ja/remote-control.md#resume-sessions-after-stopping-the-server) を参照してください | `claude remote-control --name "My Project"` |
| `claude respawn <id>` | 会話を保持したまま、[バックグラウンドセッション](https://code.claude.com/docs/ja/agent-view.md#manage-sessions-from-the-shell) を再開します。実行中または停止中。`--all` を使用してすべての実行中セッションを再開します。たとえば、更新された Claude Code バイナリを取得するため | `claude respawn 7c5dcf5d` |
| `claude rm <id>` | [バックグラウンドセッション](https://code.claude.com/docs/ja/agent-view.md#manage-sessions-from-the-shell) をリストから削除します。削除が [セッションの worktree を理由に拒否](https://code.claude.com/docs/ja/agent-view.md#what-deleting-a-session-removes) され、2 回目の `claude rm` で解決できる場合、拒否は渡すべき正確なフラグと値を出力します：`--discard-unpushed <commit>@<worktree-id>` はプッシュされていないコミットを持つ worktree をそれらのコミットとともに破棄し、`--force-remove-worktree <worktree-id>` は git または `WorktreeRemove` フックが削除できなかった worktree ディレクトリを削除します。`--discard-unpushed` には Claude Code v2.1.260 以降が必要です。また、`--force-remove-worktree` には v2.1.268 以降が必要です。会話トランスクリプトはローカルマシンに残り、`claude --resume` を通じて利用可能です | `claude rm 7c5dcf5d` |
| `claude self-hosted-runner` | このマシンまたはコンテナを [自己ホスト環境](https://code.claude.com/docs/ja/self-hosted-environments) に登録し、Claude Code クラウドセッションをインフラストラクチャ上でホストするランナープロセスを開始します。`claude self-hosted-runner setup` でガイド付きオペレーターウォークスルーを実行し、`claude self-hosted-runner doctor` で [デプロイされたランナーを診断](https://code.claude.com/docs/ja/self-hosted-environments-deploy.md#troubleshooting) し、`claude self-hosted-runner orchestrator` で [オンデマンドランナー](https://code.claude.com/docs/ja/self-hosted-environments-configuration.md#on-demand-runners) をスポーンします。Claude Code v2.1.224 以降が必要です | `claude self-hosted-runner setup` |
| `claude setup-token` | CI とスクリプト用の長期間有効な OAuth トークンを生成します。ターミナルにトークンを出力し、保存しません。Claude サブスクリプションが必要です。[長期間有効なトークンを生成](https://code.claude.com/docs/ja/authentication.md#generate-a-long-lived-token) を参照してください | `claude setup-token` |
| `claude stop <id>` | [バックグラウンドセッション](https://code.claude.com/docs/ja/agent-view.md#manage-sessions-from-the-shell) を停止します。`claude kill` も受け入れます | `claude stop 7c5dcf5d` |
| `claude ultrareview [target]` | [ultrareview](https://code.claude.com/docs/ja/ultrareview.md#run-ultrareview-non-interactively) を非対話的に実行します。結果を stdout に出力し、成功時は 0 で終了し、失敗時は 1 で終了します。`--json` を使用して生のペイロードを取得し、`--timeout <minutes>` を使用して 45 分のデフォルトを上書きします。`github.com` プルリクエストターゲットで `--post` を使用して、完了した結果を GitHub アカウントから PR に 1 つのプレーンコメントとして投稿します。`--no-post` がデフォルトです。`--post` と `--no-post` には Claude Code v2.1.227 以降が必要です。[プルリクエストに結果を投稿](https://code.claude.com/docs/ja/ultrareview.md#post-findings-to-the-pull-request) を参照してください | `claude ultrareview 1234 --json` |

サブコマンドを誤入力した場合、Claude Code は最も近い一致を提案して、セッションを開始せずに終了します。たとえば、`claude udpate` は `Did you mean claude update?` と出力します。

`claude --dangerously-skip-permissions daemon <subcommand>` は `daemon` サブコマンドを実行するため、`claude` がフラグを含むようにエイリアスされている場合でもサブコマンドは機能します。先頭の `--dangerously-skip-permissions` または `--allow-dangerously-skip-permissions` のみがこの方法で `daemon` にルーティングされます。`daemon` の前にそれ以外のフラグがある場合、サブコマンドは実行されません。

## CLI フラグ

以下のコマンドラインフラグで Claude Code の動作をカスタマイズできます。`claude --help` にはすべてのフラグが表示されるわけではないため、`--help` にフラグが表示されないからといって、そのフラグが使用できないわけではありません。

| フラグ | 説明 | 例 |
| :- | :- | :- |
| `--add-dir` | Claude がファイルを読み取り・編集するための作業ディレクトリを追加します。ファイルへのアクセスを許可するものであり、Claude Code はこれらのディレクトリからほとんどの `.claude/` 設定を[検出しません](https://code.claude.com/docs/ja/permissions.md#additional-directories-grant-file-access-not-configuration)。各パスがディレクトリとして存在することを検証します。`\\server\share` などのほとんどの[ネットワークパス](https://code.claude.com/docs/ja/errors.md#working-directory-is-a-network-path)は追加できません。これらのディレクトリをセッション間で保持するには、設定で [`permissions.additionalDirectories`](https://code.claude.com/docs/ja/settings-reference#permissions-additionaldirectories) を設定します | `claude --add-dir ../apps ../lib` |
| `--advisor <model>` | モデルエイリアス（`fable`、`opus`、`sonnet`）または完全なモデル ID を指定して、このセッションでサーバー側の[アドバイザーツール](https://code.claude.com/docs/ja/advisor.md)を有効にします。このセッションでは `advisorModel` 設定よりも優先されます。`fable` には [Fable へのアクセス](https://code.claude.com/docs/ja/advisor.md#choose-an-advisor-model)が必要です | `claude --advisor opus` |
| `--agent` | 現在のセッションのエージェントを指定します（`agent` 設定を上書きします） | `claude --agent my-custom-agent` |
| `--agents` | JSON を使用してカスタムサブエージェントを動的に定義します。[CLI で定義するサブエージェント用に記載されたフィールド](https://code.claude.com/docs/ja/sub-agents.md#choose-the-subagent-scope)を受け付けます。`--print` と併用する場合は、値の代わりにオブジェクトを含む JSON ファイルへのパスを指定することもできます。ファイル形式には Claude Code v2.1.281 以降が必要です。Claude Code は起動時に値を検証し、無効な値の場合は終了します。メッセージと、検証をスキップするフラグおよび環境変数については [`Invalid --agents configuration`](https://code.claude.com/docs/ja/errors#invalid-agents-configuration) を参照してください。検証には Claude Code v2.1.242 以降が必要です | `claude --agents '{"reviewer":{"description":"Reviews code","prompt":"You are a code reviewer"}}'` |
| `--allow-dangerously-skip-permissions` | `bypassPermissions` を `Shift+Tab` のモード切り替えサイクルに追加しますが、そのモードでは開始しません。`plan` などの別のモードで開始し、後で `bypassPermissions` に切り替えることができます。[権限モード](https://code.claude.com/docs/ja/permission-modes.md#skip-all-checks-with-bypasspermissions-mode)を参照してください | `claude --permission-mode plan --allow-dangerously-skip-permissions` |
| `--allowedTools`, `--allowed-tools` | 権限を求めるプロンプトなしで実行されるツール。ただし、[ネットワークパス](https://code.claude.com/docs/ja/permissions.md#network-paths)からの読み取りは除きます。パターンマッチングについては[権限ルールの構文](https://code.claude.com/docs/ja/settings-reference.md#permission-rule-syntax)を参照してください。使用可能なツールを制限するには、代わりに `--tools` を使用します。ここで[タスク追跡ツール](https://code.claude.com/docs/ja/tools-reference.md#task-tool-availability)のいずれかを指定すると、Claude Code はセッションでそれらのツールの利用も有効にします | `"Bash(git log *)" "Bash(git diff *)" "Read"` |
| `--append-subagent-system-prompt` | すべての[サブエージェント](https://code.claude.com/docs/ja/sub-agents.md)のシステムプロンプトの末尾にカスタムテキストを追加します。ネストされたサブエージェントも対象ですが、会話自体のプロンプトを再利用する[フォークされたサブエージェント](https://code.claude.com/docs/ja/sub-agents.md#fork-the-current-conversation)は除きます。`-p` を使用した非対話モードでのみ適用されます。Claude Code v2.1.205 以降が必要です | `claude -p --append-subagent-system-prompt "Cite file paths in every answer" "query"` |

### システムプロンプトフラグ

Claude Code には、システムプロンプトをカスタマイズするための 5 つのフラグがあります。4 つはプロンプトのテキストを設定するもので、`--system-prompt-snapshot` では、会話が開始時のテキストを保持し続けるかどうかを制御します。5 つすべてが対話モードと非対話モードの両方で機能します。

| フラグ | 動作 | 例 |
| :- | :- | :- |
| `--system-prompt` | デフォルトのプロンプト全体を置き換えます | `claude --system-prompt "You are a Python expert"` |
| `--system-prompt-file` | ファイルの内容で置き換えます | `claude --system-prompt-file ./prompts/review.txt` |
| `--append-system-prompt` | デフォルトのプロンプトに追加します | `claude --append-system-prompt "Always use TypeScript"` |
| `--append-system-prompt-file` | ファイルの内容をデフォルトのプロンプトに追加します | `claude --append-system-prompt-file ./style-rules.txt` |
| `--system-prompt-snapshot` | `off` の場合、リクエストごとにプロンプトを再構築します。デフォルトの `on` の場合、[記録が適用される](#system-prompt-flags-in-resumed-conversations)ときは記録されたプロンプトを再利用します | `claude --append-system-prompt "Draft rules" --system-prompt-snapshot off` |

これらのフラグは組み合わせて使用できます。デフォルトのプロンプトを置き換えたうえで独自のテキストを追加するには、`--system-prompt` または `--system-prompt-file` と一緒に `--append-system-prompt` または `--append-system-prompt-file` を渡します。Claude Code v2.1.283 以降では、`--append-system-prompt` と `--append-system-prompt-file` のように、フラグとそのファイル形式を一緒に渡すこともでき、Claude Code は両方を使用します。

たとえば、ファイルのスタイルガイドと追加の指示 1 つの両方を追加するには、シェルで次のように実行します：

```bash theme={null}
claude -p --append-system-prompt-file ./style.md --append-system-prompt "Always reply in French" "Summarize README.md"
```

Claude は、デフォルトのシステムプロンプトの後に `style.md` の内容、空行、`Always reply in French` が続いたものを受け取ります。`--append-system-prompt-file` より前に `--append-system-prompt` を渡した場合でも、ファイルの内容が先になります。

置き換えるテキストが、毎回同じ指示と実行ごとに変わるコンテキストを組み合わせたものである場合は、指示とコンテキストの間に `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` のみを含む行を追加します。Claude Code は最初にあるその行でプロンプトを分割してその行を削除するため、その行より上の部分はキャッシュされたままとなり、下の部分は変更されます。Claude Code v2.1.275 以降が必要です。分割が適用される設定については、[カスタムプロンプトの静的な部分をキャッシュする](https://code.claude.com/docs/ja/agent-sdk/modifying-system-prompts.md#cache-the-static-part-of-a-custom-prompt)に一覧があります。

Claude Code のデフォルトのアイデンティティがタスクに合っているかどうかで選択してください。Claude をコーディングアシスタントのままにしつつ、追加のルール（呼び出しごとの指示、出力のフォーマット、`-p` スクリプトのドメインコンテキストなど）にも従わせたい場合は、追加フラグを使用します。追加ではデフォルトのツールガイダンス、安全性に関する指示、コーディング規約が保持されるため、異なる部分だけを指定すれば済みます。サーフェス、アイデンティティ、または権限モデルが Claude Code と異なる場合、たとえば人間が監視しないパイプライン内のコーディング以外のエージェントなどには、置き換えフラグを使用します。置き換えると、ツールガイダンスや安全性に関する指示を含むデフォルトのプロンプトがすべて失われるため、タスクに引き続き必要なものはユーザー自身が用意する必要があります。

切り替えたりプロジェクト全体で共有したりできる永続的なペルソナには、[出力スタイル](https://code.claude.com/docs/ja/output-styles.md)を使用します。Claude に常に従わせたいプロジェクトの規約には、[CLAUDE.md](https://code.claude.com/docs/ja/memory.md) を使用します。同じ判断について、[システムプロンプトに関する Agent SDK ガイド](https://code.claude.com/docs/ja/agent-sdk/modifying-system-prompts.md#decide-on-a-starting-point)でより詳しく説明しています。

#### 再開した会話でのシステムプロンプトフラグ

デフォルトでは、Claude Code は会話の最初のリクエスト時に、システムプロンプトフラグのテキストを適用したうえでシステムプロンプトを 1 回だけ構築し、セッションに記録します。会話が圧縮されるまでは、以降のすべてのリクエストでその記録されたプロンプトが使用されます。これは `--resume` または `--continue` で会話に戻った後も同様です。その後の起動時に異なるシステムプロンプトフラグのテキストを渡した場合（またはフラグを渡さなかった場合）、その変更は会話が圧縮された時点、または新しい会話を開始した時点で有効になります。

[クラウドセッション](https://code.claude.com/docs/ja/cloud-environments.md)以外で、`--bare` を渡すか `CLAUDE_CODE_SIMPLE=1` を設定して [bare モード](https://code.claude.com/docs/ja/headless.md#start-faster-with-bare-mode)で Claude Code を開始した場合、`--system-prompt-snapshot on` を渡さない限り記録はオフのままです。v2.1.268 より前は、[機能フラグを取得](https://code.claude.com/docs/ja/env-vars.md#features-that-need-feature-flag-fetching)しないセッション（Amazon Bedrock、Google Cloud's Agent Platform、Microsoft Foundry 上のセッションを含む）ではリクエストごとにプロンプトが再構築され、`--system-prompt-snapshot` は効果がありませんでした。

代わりにリクエストごとにプロンプトを再構築するには、`--system-prompt-snapshot off` を渡します。たとえば、`--continue` の実行をまたいでプロンプトの文言を繰り返し調整する場合に便利です。v2.1.265 より前は、いずれかのシステムプロンプトフラグを渡すと、`--system-prompt-snapshot on` を渡さない限り記録もオフになっていました。
